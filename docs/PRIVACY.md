# Hingy privacy policy — publisher-review draft

Last prepared: September 14, 2026. **This is the developer-preview policy, not an assertion that public-release publisher details have been completed.** Before App Store submission, the owner must supply the verified legal publisher and public contact, publish the full policy at the configured URL, and audit it against the exact release build.

The app does not create accounts, record microphone input, contain analytics or advertising SDKs, or automatically transmit sounds, settings, or hinge activity to an app-operated server. It has no remotely hosted sound catalogue and does not automatically attach data to support requests.

Selected settings and copies of imported audio are stored in the app's private Application Support directory. The activity label is transient, not a saved fold-history log. The Files importer accesses the file selected by the user. Device/cloud backups may include local app data according to the user's iOS/backup settings; the project does not operate its own cloud synchronization.

Deleting the app removes its active local data. Offloading can retain documents and data, and backup removal is separate. There is no project account to delete. The app cannot delete the user's original source file or copies held by a backup provider.

Opening external support or policy links uses the relevant website/service. Information voluntarily posted to GitHub or sent by email, as well as that service's handling of it, is separate from automatic app collection. GitHub issues are public: do not include private audio, credentials or personal information. Development support is currently through https://github.com/seichris/duo-sound/issues ; this must not be mistaken for a completed public-release legal/contact declaration.

The generated website contains no analytics scripts, ad tags or forms. A future web host can process requests and operational logs under its own policy. Hosting has not been deployed by this PR; select and disclose it before claiming that the website collects no data. Apple-provided distribution/testing/diagnostic services have their own data handling; audit any App Store Connect/TestFlight sharing settings separately.

Before release, add the legal publisher and support email from `release/readiness.json`, document any jurisdiction-specific details that apply to the actual seller/storefronts, verify the website and in-app links, and recheck the final Xcode privacy report. Do not copy another app's legal identity or guess required-reason API codes.
